# Devices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The phone app pairs with ScadBuddy as a device. Pages, flows and the assistant then call its four methods: `nfc.read`, `nfc.write`, `code.scan` and `camera.capture`. Each call streams its events and ends with a stored read.

**Architecture:** A new Go package `tools/go/core/internal/devices` owns the pairing, the tokens, a WebSocket per online device, the calls with their events, and the device reads. A call that reaches a pod which does not hold the device's socket goes over core's Postgres bus. The app (`app/ScadBuddy`) pairs through a `scadbuddy://pair` link, keeps the token in `SecureStorage`, holds the socket while it is in front, and answers calls with its native NFC and camera.

**Tech Stack:** Go (core, pgx, the realtime package's RFC 6455 server), Postgres, .NET MAUI Android, React (the Devices page).

**Spec:** `docs/superpowers/specs/2026-11-27-devices-design.md`

## Global Constraints

- Only four capabilities: `nfc.read`, `nfc.write`, `code.scan`, `camera.capture`. ScadBuddy is not a device platform.
- Pairing code: at least 128 random bits. Only its hash is stored. It is single-use and expires in 10 minutes.
- Device token: at least 256 random bits. Only its hash is stored. It expires after 1 hour idle, and each authenticated frame or call moves the expiry to now + 1 hour. Hard cap: 30 days from pairing. Both values are settings.
- Heartbeat every 30 s. A call's deadline is at most 2 minutes.
- Device-token routes (the pairing claim, the socket, the device upload) check the token in every auth mode. Person routes follow the global mode. Never `SCADBUDDY_AUTH_MODE=enforce` on prod.
- A Bambu tag is never written. Both the device and core refuse it.
- Bytes never go in a socket frame, and never as base64 in JSON (#2479). Tag dumps go as kind `tag_dump`, photos as kind `scan_image`.
- One new migration file in `backend/scadbuddy/migrations/`, named `$(date -u +%Y%m%dT%H%MZ)_devices.sql`.
- New backend code is Go. Only core and the API hold SQL.
- An outward call made by the assistant or a flow needs a pending action. A person's own click on a page is the approval.

## Review Focus

1. **Two pods.** The caller's request lands on pod A, and the device's socket is on pod B. The call still reaches the device, and its events reach the caller (Task 4, `TestCallAcrossHubs`).
2. **The socket drops in the middle of a call.** The call ends with outcome `offline` once its deadline passes. It never hangs (Task 4, `TestCallDeviceGoneMidCall`).
3. **Revoke while online.** Revoking a device closes its socket at once. Its next frame, upload or reconnect gets 401 (Task 3, `TestRevokeClosesSocket`).
4. **Old or reused codes.** A pairing code used twice, or used after 10 minutes, gets 410. It makes no device (Task 2, `TestPairCodeSpentOnce`).
5. **A hostile result frame.** A device's result names a blob the device did not upload, or a kind that does not match its method. Core refuses it. It writes no `device_reads` row, and the call ends with `error` (Task 5, `TestResultRefusesForeignBlob`).

**Interfaces:**
- Produces `func Routes(pool *pgxpool.Pool, keys *seal.Keys) map[string][]auth.Public`, which is area `devices`.
- Person routes, class `api`:

### Task 4: Calls and their events

**Files:**
- Create: `tools/go/core/internal/devices/calls.go`
- Test: `tools/go/core/internal/devices/calls_test.go`

**Interfaces:**
- `POST /api/v1/devices/{id}/calls {method, args, timeout_s}` answers `202 {call_id}`. It answers `409 {"error":"offline"}` when no pod holds the socket, and `422` for a method the device did not announce. With `?wait=true`, it holds the request until the result (200) or the deadline (504).
- `GET /api/v1/devices/calls/{id}` answers `{call, events: [...], result}`.
- Each event is a `device_call_events` row and is published on the change stream as `device.call.event`, with the call's id and seq.
- A call to a device on another pod goes through a bus NOTIFY on channel `devices_call`. The pod that holds the socket sends the `call` frame.
- `timeout_s` defaults to 60 and is at most 120.

### Task 5: Device uploads and device reads

**Files:**
- Create: `tools/go/core/internal/devices/reads.go`
- Test: `tools/go/core/internal/devices/reads_test.go`

**Interfaces:**
- Device route: `POST /api/v1/devices/uploads?call=<id>&kind=tag_dump|scan_image`, with a raw body. It stores the bytes with `blobstore.Put`, or with whatever single store path is on main by then (#8138 and #8167 merge theirs into one). It answers `{key}`.
- A `result` frame for `nfc.read` carries `{read: {blob_key, uid, tech, complete, missing_blocks}}`. For `code.scan` and `camera.capture` it carries `{read: {blob_key, media_type}}`. Core writes `device_reads` and ends the call with `{read_id, uid?, complete?}`.
- `GET /api/v1/devices/reads/{id}` answers the row. `GET /api/v1/devices/reads/{id}/blob` answers the bytes, with their media type and `nosniff`.
- The `tag_dump` blob is JSON `{uid, tech, blocks: [{index, data_hex}], records: [...]}`. It holds no key trailer: blocks 3, 7, …, 63 are refused.

- The socket is held only while the app is in front. It is closed in `OnPause` and opened again in `OnResume`.
