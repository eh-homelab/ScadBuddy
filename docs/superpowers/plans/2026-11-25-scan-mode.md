# Hand-held Scan Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A first-class, context-free Scan mode: a nav entry opens the always-scanning phone page, and a tap of any tag opens what it names: a spool's bound tag, a tag or label that carries a typed code (`L-12`, `S-142`, a `/x/<code>` URL) or a `scadbuddy:spool:<id>` text.

**Architecture:** The existing phone page (`/filament/scan`, #7273) moves to a top-level `/scan` with a nav entry; the old address redirects. `POST /filament/tags/reads` learns to read a code out of the tag's NDEF records when no spool holds the tag, answering `resolved` (the `/codes/{code}` shape) and `next: "open_code"`. The page shows a code's card with Open, and an "Open what I scan at once" switch that navigates on each read.

**Tech Stack:** FastAPI + psycopg (backend), React 19 + react-router + msw mocks + vitest (frontend), Web NFC.

**Spec:** The owner's request of 2026-11-25 ("a hand-held scan mode that is always scanning … I want it to essentially load anything, even a prefixed tag"), on top of `docs/superpowers/specs/2026-11-23-web-nfc-tags-design.md` (the phone page) and #6955 (typed codes, `backend/scadbuddy/codes/`). This plan is the short design: there is no separate spec.

## Short design (approaches)

1. **Nav entry only** (link the existing page from the shell): one line, but a tag that carries a place code or a label's code still shows "New tag". Rejected alone: the owner wants it to load anything.
2. **Resolve codes on the phone** (parse records in the browser, call `GET /codes/{code}`): no API change, but the agent's NFC read jobs (which answer the same `TagReadResult`) would not learn it, and two parsers drift. Rejected.
3. **Resolve codes in `tags.read_on`** (chosen): one rule server-side, the page and the agent's read jobs both get `resolved`; the page adds a card and the switch.

Decisions (mine, the owner can correct):
- The route is top-level `/scan`, not a new `/filament/*` route: scanning is for any thing (the Inventory epic #6949 will add items and units). `/filament/scan` redirects.
- A tag a spool holds still opens the spool (today's rule) even if its records also carry a code: the binding is the stronger claim.
- A code wins over "new tag": a tag that names a place is not offered for binding to a spool. The card still lets the person bind it from the spool's own page later, so nothing is lost.
- "Open what I scan at once" is a remembered switch (localStorage `scadbuddy.scan.openAtOnce`, default off). With it on, a read whose `next` is `open_spool` or `open_code` navigates straight to the thing; coming back to `/scan` starts the scan again by itself, and falls back to the Scan button if the browser refuses.

## Global Constraints

- Never commit `backend/openapi.json` or `schema.d.ts`; run `pnpm gen:api` after the model change.

## Review Focus

1. A URL record whose path is `/x/L-4` under any origin or with a query (`https://host/x/L-4?from=label`) resolves; a URL whose last segments are not `x/<code>` (`https://host/filament/spools/…`) does not. Test in Task 1.
2. A text record in UTF-16 (`encoding: "utf-16"`) holding `S-142` resolves; bytes that are not valid text in the named encoding are skipped, never raised. Test in Task 1.
3. A code that parses but names no row (`L-999999`) is no `resolved`: the read is `bind_or_create` (a UID) or `none`. Test in Task 1.
4. A `scadbuddy:spool:<id>` text for an archived or unknown spool: archived resolves with `archived: true`; unknown is skipped. Test in Task 1.
5. With "Open at once" on, a `bind_or_create` read does not navigate (there is nothing to open); the page stays and shows the New tag card. Test in Task 4.

- [ ] **Step 3: Implement `tag_codes.py`**

`code_in` walks the records in order. A `url` record: decode UTF-8 (skip on failure), `urllib.parse.urlsplit`, take the path's segments with empty ones dropped; when the last two are `x` and a text `parse_code` accepts, return the code. A `text` record: decode in `encoding or "utf-8"` with `decode_text` (reuse the UTF-16 rule the frontend's `decodeText` documents: no byte order named means BOM, else big-endian; skip on failure); strip; `parse_code` → return; else a match of `^scadbuddy:spool:([0-9a-f-]{36})$` (case-insensitive) → return `UUID`. Any other record type is skipped. Never raise on bad bytes.

`resolve_records(conn, records)`: `found = code_in(records)`; a `Code` → `resolve(conn, found)`; a `UUID` → one query `SELECT number, archived_at FROM filament_spools WHERE id = %s` → `Resolved(kind="spool", id=..., code=format_code("S", number), name=None, archived=...)` or `None` when no row.
