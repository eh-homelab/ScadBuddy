# Native Print Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ScadBuddy's own print library (folders and files in Postgres, bytes as `library` blobs in the content store), chosen by `library_backend` and served by the unchanged `/print/library/*` routes, so `bambuddy-fs` mounts it with no change (#3827).

**Architecture:** A new feature package `backend/scadbuddy/print_library/` holds the rows (`store.py`), the library over rows plus `ContentStore` (`native.py`), the read protocols both libraries satisfy (`reads.py`), the component that picks one at start (`component.py`), the trash purge (`sweep.py`) and the filing of saved outputs (`filing.py`). `NativeLibrary` answers the same read methods `BambuddyClient` does, with the same Bambuddy models (`Folder`, `LibraryListRow`, `LibraryFile`, `LibraryPlates`), so `list_library`, `search_library`, `LibrarySource` and the preview/objects readers run unchanged over either. The routes and the existing operation kinds keep their names and shapes and dispatch on the component's backend; the print worker routes a file id by its range.

**Tech Stack:** Python 3.12, psycopg 3, FastAPI, Temporal (temporalio), the existing `ContentStore`; Go 1.26 (bambuddy-fs live test); React/TypeScript (Settings field); GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-16-own-store-slicer-rust-workers-design.md` §4.5 (on §4.1-§4.3), §8.

## Global Constraints

- `library_backend`: `bambuddy` | `native`, `applies: restart`, default `bambuddy`, seeded by `SCADBUDDY_LIBRARY_BACKEND` (spec §8).
- Tables `library_folders` (id, parent_id, name, created_at) and `library_files` (id, folder_id, name, size, sha256, blob key, media type, created_at, updated_at), plus the columns Ruling 2/8/9 add (spec §4.5).
- A fifth `BlobKind`, `"library"`, never in `SWEPT_KINDS`; a file's blob is released only when its row is deleted (spec §4.5).
- `/print/library/*` request and response shapes do not change; no new public `/api/v1` operation. The generated API files are never committed.
- One id space at a time: on `native` the routes answer native ids only, on `bambuddy` Bambuddy's (spec §4.5).
- Saved outputs are filed under `<Template title>/` (spec §4.5).
- The Bambuddy print path still uploads its copy to Bambuddy's library (`send.py`), unchanged (spec §4.5).
- `bambuddy-fs` changes nothing but its README wording ("Mounts ScadBuddy's print library"); its mount test runs against both backends in CI (spec §4.5).
- `store_backend=local` is unchanged (spec §4.6).
- Schema changes are new files `backend/scadbuddy/migrations/$(date -u +%Y%m%dT%H%MZ)_<slug>.sql`; never edit a merged one.
- A new backend service is a `Component`, never an `AppState` field; library writes are operation kinds on the `library` queue.
- `Housekeeping.run` stays replay-compatible: a new sweep goes behind `workflow.patched`; `tests/fixtures/housekeeping_histories/` must still replay.
- Every measured or external fact in a docstring or doc cites its source (#259).

## Rulings

Where the spec leaves a choice open, decided here:

1. **Native ids start at 1 000 000 000** (`NATIVE_ID_BASE`), for files and folders (`GENERATED BY DEFAULT AS IDENTITY (START WITH 1000000000)`). The reason: a mount's cache is keyed by API host and file id (bambuddy-fs README "Caching and uploads": "a file's bytes are immutable per ID"), and remembered choices, print links and `output_bambuddy_uploads` are keyed by `library:<id>`. If the id ranges overlapped, a flip of `library_backend` would serve one file's cached bytes for another. Bambuddy's SQLite ids are far below 10^9. The Kiota Go client types ids as `int32` (`tools/go/scadbuddy-client/client/models/library_entry.go` `GetId() *int32`), so the base also leaves about 1.1·10^9 ids under 2^31. `is_native_id(id)` is how a process that does not know the API's backend (the print worker) routes an id.
2. **A native delete moves the file to a trash** (`deleted_at`), and `/restore` brings it back under its own id, matching `trashed: true` and the mount's documented Undo. A housekeeping sweep purges trashed rows after `LIBRARY_TRASH_TTL = 30 days` and releases their blobs. Without a trash, an `rm -rf` on the mount would lose files with no way back. The sweep obeys the sweeps switch (`asset_sweep_interval` 0 stops it), as the asset sweep does, because it deletes user data.
3. **`native` needs a content store.** It is refused on `store_backend=local` in the Settings save and at start (`StoreNotReadyError`, `NATIVE_LIBRARY_NOT_READY`). It is allowed on `s3` and on `bambuddy`. On `local` there is no `ContentStore` (`factory.py` `build_store`), and spec §4.6 says `local` does not change.
4. **The blob key is per file**, `library-file-<id>`. Identical bytes still share one backend object, because `ContentStore._store` reuses an object by sha and `_release` removes it only when no index row names it. A copy indexes the source's object under the copy's key (`ContentStore.link`) and moves no bytes.
5. **Names need not be unique**, in a folder or among siblings, as in Bambuddy (bambuddy-fs README "Names"; `library_file_moves.resolve_folder`'s 409 for a path two folders share).
6. **Printing a native file works**, through `LibrarySource` with a separate `files` reader: the file's own reads go to the native library, and everything else still goes to Bambuddy. `origin_id` is `None` for a native id, since Bambuddy does not have that file (`send.recorded_copy_to_read`). The print worker reads native files through hidden internal routes (`RemoteLibrary`, after `RemoteOutputs`). Without this, the Library page's Print would break on `native`. A native file that has no laid-out payload is uploaded raw as the Bambuddy copy, and that copy's id is queued (`LibrarySource.raw_copy`). That covers a sliced `.gcode.3mf`, an STL that will not wrap, and a file past `MAX_DOWNLOAD_BYTES`. Otherwise those files would meet `Printable.fetch`'s 409 "has no 3MF to upload" (`print_source.py:331-337`), which is where a Bambuddy file uses `origin_id` instead.
7. **Print destinations stay Bambuddy's folders** (`/print/projects`, a print request's `folder_id`, `last_project_id`, `require_destination_folder`) on both backends. The Bambuddy print path files into Bambuddy (spec §4.5), and the recent `print_run.py` `ResolvedProject`/`prepare_run` folder check and `print_activities.check` are untouched.
8. **Filing.** `output_create` on `native` files the output's `model.3mf` into the top-level folder named `store.bambuddy.folder_name(title)`. It takes the oldest such folder, or makes one under an advisory lock. The file is named `OutputSource.inbox_name` (`download_filename(meta)`) and the row records `output_id` and `filed = true`. A move clears `filed`. An output delete with `delete_inbox_copies` trashes the files still `filed`, matching what the inbox delete removes on Bambuddy. Filing failure never fails the save: the save is the output, and filing is logged and retried by nothing.
9. **Plates are read once, at upload** (`render.bambu3mf.plates_of` on the local claim file), into `plates jsonb` and `has_thumbnail`. `/plates` and the listing then download nothing. Thumbnails are read on demand from the blob, and the content store's download cache makes repeats local.
10. **A native download ignores `Range`** and answers `200` with the whole body, `content-length`, `etag: "<sha256>"` and `accept-ranges: none`. bambuddy-fs reads whole files (`api.go` `Download`).
11. **`StoreFullError` on a native upload, copy or filing is a 507**, as `api/assets.py` maps it. bambuddy-fs then queues the write as unsent, not refused.
12. **Native search reads Postgres per request** through `search_library` unchanged, with no `library_search` snapshot, because a query is cheap there.
13. **`/names`' 502 "none of these" rule is Bambuddy's only.** It guards a misrouted base URL. On `native`, ids not found answer `name: null`.
14. **Native folders carry `project_id: None`. Native files carry `is_external: false` and `print_count: 0`.** Bambuddy projects link Bambuddy folders, and ScadBuddy keeps no per-file print count.
15. **The kinds keep their names** (`library_file_delete` … `library_file_upload`) and dispatch at run time on the component's backend. `PrintLibrary.backend` is read lazily on first use and then cached, never at component build. `build_all` runs before the lifespan opens the settings pool (`api/deps.py:298`, `main.py:1235`), and `AppState.store` is set only at `main.py:1248`. An operation recorded under the other backend then meets an id from the other range, which is a 404, never another file (Ruling 1).
16. **CI's live mount runs in the `image` job** (the only place the image exists, ci.yml's comment on the job), once per backend. Each run gets a container with its own database and Temporal namespace. `native` stores on S3 through `moto_server` from the test image; `bambuddy` points at a small fake Bambuddy library server (`tests/support/fake_bambuddy_library.py`) from the same image.

## Spec corrections

- §4.5 says the output's folder is `<Template title>/` "as the Bambuddy inbox layout is today". In fact a sent output's inbox copy sits at the inbox's top level, named `Printable.inbox_name` (`bambuddy/send.py` `upload_copy`, `folder = … settings.library_folder_id`). `<Template title>/` folders exist only as the Bambuddy store's `Work/` parents (`store/bambuddy.py` docstring). The plan files native outputs under a top-level `<Template title>/`, as the spec intends.
- §4.5 says that with `library_backend=native` "the Bambuddy inbox and `Work/` folders are no longer required for the store to start". The store needs the inbox only on `store_backend=bambuddy` (`store/backends.py` `build_backend`), and `library_backend` does not change that. What `native` removes is Bambuddy from browsing and saving. Run with `store_backend=s3`, nothing at start needs Bambuddy. The plan adds no start-time change for the inbox, and Task 9 edits spec §4.5 to say so.
- §4.5 says bambuddy-fs's "mount tests run against both backends". The existing mount tests run against an in-process fake (`internal/fsys/fake_test.go` `fakeLibrary`), not a ScadBuddy, so there is no backend to vary. Task 10 adds a live mount test against a real container.
- §4.5's `library_files` columns are not enough for the routes' shapes and the trash: `deleted_at`, `output_id`, `filed`, `plates`, `has_thumbnail` are added (Rulings 2, 8, 9). "The row's delete releases it" holds for the purge; a user delete first moves the file to the trash.

## Review Focus

1. **A flip of `library_backend` while a mount runs.** A cached Bambuddy id must never be served as a native file: Bambuddy-range ids answer 404 on `native` (Task 4 `test_a_bambuddy_range_id_is_404_on_native`).
2. **Two files with the same bytes.** Deleting (purging) one must leave the other readable (Task 3 `test_purging_one_of_two_identical_files_keeps_the_other`).
3. **A crash between the blob put and the row insert** leaves an index row `library-file-<id>` with no file. The sweep removes it once past grace and keeps a younger one (Task 6 `test_an_orphan_library_blob_goes_after_grace`).
4. **A folder moved into its own subtree.** Answered 422 and nothing changes, rather than a cycle the tree walk ends early on (Task 5 `test_a_folder_cannot_move_under_itself`).
5. **A purge racing a restore.** A file restored after the sweep listed it must survive with its blob (Task 6 `test_a_restore_between_list_and_purge_keeps_the_file`).
6. **A sliced or unwrappable native file printed through Bambuddy.** The raw copy is queued, and the run never answers a 409 (Task 7a `test_a_native_gcode_3mf_queues_its_raw_copy`, `test_a_native_stl_that_will_not_wrap_queues_its_raw_copy`).
7. **A large upload (above the 64 MiB multipart threshold) through the route.** It streams from the claim file and never reads whole. The download's `content-length` and sha match (Task 5 `test_a_large_upload_streams`, 80 MiB of zeros in a sparse file).

    - `thumbnail(file_id: int, plate: int | None) -> bytes | None` (`Metadata/plate_<n>.png`, `plate=None` meaning `Metadata/thumbnail.png`, else plate 1, read from a spool copy of the blob).
    - `names(ids: list[int]) -> list[tuple[int, NativeFile | None]]`.
